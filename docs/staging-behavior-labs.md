# 실험실(캘린더 · AI 에이전트 · AI 세그먼트) - 스테이징 동작 메모 (2026-10-08)

스테이징 콘솔 공개 번들(buildId `Q-tOYo7BMgpuoKSGYkmC0`, 404 페이지 `__NEXT_DATA__`로 재확인)과 로케일 파일(`/locales/ko/common.json`, `labs.json`, `aiAgent.json`, `in-app-message.json`)에서 읽은 동작. 로그인·API 호출 없이 정적 파일만 봤다(페이지 청크 + 공용 청크 + 채팅 패널 지연 로드 청크 `2506.*.js`). 프로토타입은 이 동작을 따르고, 모양은 Figma 시안을 따른다.

- 문구는 「」 안에 그대로 옮김. `{{x}}`는 치환 값. 로케일에 없고 코드에 박힌 문구는 "(하드코딩)" 표시.
- API 기본 주소가 둘이다.
  - **v1**: `https://staging-service-api.flarelane.com/v1/projects/{projectId}` (기존 화면들과 같음)
  - **labs**: `https://staging-service-api.flarelane.com/labs/projects/{projectId}` (v1의 `/v1`을 `/labs`로 바꾼 주소). 아래에서 경로 앞에 `labs:`/`v1:`로 구분.
  - AI 채팅은 HTTP가 아니라 **socket.io**: `https://staging-ai.flarelane.com` 의 `/chat` 네임스페이스(websocket 전용).
- 공통 에러 처리(axios 공용 훅): 서버 `message`를 빨간 토스트로, 응답이 없으면 「인터넷 연결을 확인해 주세요.」. 예외는 각 절에 따로 적음.
- 날짜 표기 함수: 기본 `yyyy.LL.dd HH:mm:ss`(값 없으면 「-」). 숫자는 `toLocaleString("ko-KR")`(0/빈 값은 「0」).

## 주소 (빌드 매니페스트 기준)
| 주소 | 화면 | 필요한 프로젝트 플래그 |
|---|---|---|
| `/labs/calendar` | 캘린더 | `isLabsCalendarEnabled` |
| `/labs/ai-agent` | AI 에이전트(설정 화면) | `isLabsChatEnabled` |
| `/labs/ai-segment` | AI 세그먼트 | `isLabsAiSegmentEnabled` |

- `/labs` 자체(인덱스)나 다른 하위 주소는 매니페스트에 **없음** → `/labs`로 직접 가면 404 페이지일 것.
- 쿼리 파라미터: 세 페이지 모두 읽는 쿼리 없음(상태는 전부 내부 state + localStorage).
- 세 페이지 모두 `getServerSideProps` 있음 → 서버 쪽 리다이렉트 여부는 번들로 알 수 없음.
- 플래그는 프로젝트 상세(`GET v1:/projects/{id}`, 응답의 `isLabsCalendarEnabled` · `isLabsChatEnabled` · `isLabsAiSegmentEnabled` · `isLabsMcpEnabled`)에서 읽음.
  - 페이지 가드: 프로젝트 상세가 로드됐는데 플래그가 false면 `router.replace("/dashboard")`. 그동안은 빈 레이아웃만 그림.
- 왼쪽 메뉴: 「설정」 그룹 마지막에 「실험실」(접는 부모 메뉴) → 하위 「캘린더」 · 「AI 에이전트」 · 「AI 세그먼트」
  - 하위 메뉴는 각자 플래그가 켜진 것만 보이고, 셋 다 꺼져 있으면 「실험실」 자체가 사라짐.
  - 부모 「실험실」은 이동하지 않고 펼침/접힘만(높이 애니메이션, 화살표 회전). 처음엔 현재 주소 첫 구간이 `/labs`면 펼쳐진 상태.

## 1. AI 에이전트 `/labs/ai-agent`

이 페이지는 채팅 자체가 아니라 **채팅 런처 켜기/끄기 + AI 컨텍스트(설정) 편집** 화면이다. 실제 채팅 패널은 콘솔 전역(모든 페이지)에 붙는다 → 2장.

### 1-1. 레이아웃 (위→아래, 간격 32px)
1. 페이지 제목 「AI 에이전트」 (heading4)
2. 카드 「AI 에이전트」
   - 설명 「콘솔 우하단에 에이전트를 노출합니다. 캠페인을 분석하고 운영할 수 있습니다.」
   - 오른쪽 토글 스위치(44×18, `role="switch"`, aria-label 「AI 에이전트 켜기」)

   - 클릭 → 런처 표시 토글. **끄면 열려 있던 채팅 패널도 닫힘.** 저장 토스트 없음(브라우저 로컬 저장).

## 2. AI 채팅 패널 (전역, `isLabsChatEnabled` 프로젝트에서만)

### 2-1. 켜짐 조건 · 저장 상태
- 플래그가 켜진 프로젝트면 소켓은 항상 연결(`auth: {token, projectId, timeZone(브라우저)}`). 런처/패널 UI는 「AI 에이전트」 토글을 켰을 때만 보임.
- localStorage: 패널 열림 `flarelane_chat_open`, 전체화면 `flarelane_chat_exp`, 런처 표시 `flarelane_chat_launcher`, 패널 너비 `flarelane_chat_pw`, 플랜 칸 너비 `flarelane_chat_plw`, 마지막 대화 `flarelane_chat_sid`(다시 열면 그 대화 자동 선택).
- 프로젝트를 바꾸면 대화 목록·상태 전부 초기화.

### 2-2. 런처 (패널이 닫혀 있을 때, 화면 우하단 right 24 / bottom 24)
- 52px 원형 버튼(AI 캐릭터 아이콘), 툴팁 「FlareLane AI」 + 단축키 `⌘ E`(Mac) / `Ctrl E`. 클릭 → 패널 열림(도킹).
- 위에 쌓이는 것(아래→위):
  - **추천 쇼트컷 칩**: 사용자가 5초간 마우스/키 입력이 없으면 1.5초 뒤 서버에 현재 화면 기준 추천을 요청(`chat:suggest`). 요청 중엔 점 3개 애니메이션(aria 「쇼트컷을 준비하는 중」) + 런처 테두리 회전 그라데이션. 받은 칩(최대폭 260px 알약) 클릭 → 패널 열고 **새 대화**로 그 prompt 전송. 같은 주소에선 한 번만 요청, 주소 바뀌면 초기화.
  - **해야 될 작업 칩**(기한 지난 리마인더가 있을 때): 「해야 될 작업 · {{title}}」 + 2건 이상이면 「+{n}」(하드코딩 "+"). 클릭 → 패널 열림.

### 2-3. 패널 모양 · 크기
- **도킹**(기본): 오른쪽 고정, 기본 너비 480px(드래그로 380~760, 화면폭-560 이하). 왼쪽 가장자리 6px 드래그 핸들(aria 「채팅 창 크기 조절」). 본문 콘텐츠가 패널 폭만큼 밀림(가려지지 않음).
- **전체 화면**: 너비 = 화면폭 - 왼쪽 사이드바 폭. 왼쪽에 대화 목록 사이드바(260px)가 붙음. 열면 콘솔 왼쪽 메뉴가 자동으로 접히고, 닫으면 원래대로. 다른 페이지로 이동하면 자동으로 도킹으로 돌아옴. 전체 화면에서 링크를 Ctrl/⌘+클릭하면 그 경로로 이동.
- 단축키(런처가 켜져 있을 때만):
  - `⌘/Ctrl + E`: 닫힘 → 도킹 열기 / 도킹 → 전체 화면 / 전체 화면에서 **300ms 이상 누르고 있으면 「엿보기」**(패널 투명, 손 떼면 복귀)
  - `⌘/Ctrl + P`: 플랜모드 켜고 끄기(닫혀 있으면 도킹으로 열면서). 답변 중엔 무시.
- 결과를 화면에 적용한 뒤에는 전체 화면이 도킹으로 내려가고, 입력창 위에 「전체화면으로 돌아가기」 버튼이 생김.

### 2-4. 헤더 (높이 56px)
- 도킹일 때 왼쪽: 현재 대화 제목 드롭다운(제목 없으면 「새 대화」) + 설정 아이콘
  - 드롭다운(280px): 대화를 「오늘」 · 「지난 7일」 · 「이전」 그룹으로, 비면 「대화 내역이 없습니다」. 각 줄 오른쪽 휴지통(aria 「대화 삭제」).
- 전체 화면일 때: 왼쪽 목록이 접혀 있으면 「대화 목록 열기」 아이콘, 가운데 대화 제목(최대 40%), 오른쪽 그룹에 설정 아이콘.
- 오른쪽 아이콘들(툴팁 있음): 설정 「AI 설정」(프로젝트 AI 설정이 비어 있으면 빨간 점) · 「해야 될 작업」(종 모양, 기한 된 것 있으면 점) · 「새 대화」(+) · 「전체 화면으로 보기」/「패널로 보기」(전체 화면일 때 툴팁 보조줄 「꾹 누르면 콘솔 엿보기」) · 「닫기」(X)
- 설정 → 1-2의 「AI 설정」 모달. 닫히면 빈 설정 여부 다시 확인.
- 「해야 될 작업」 팝오버(300px): 제목 「해야 될 작업」, 비면 「해야 될 작업이 없어요」. 줄마다 제목 · 상세(2줄) · 「지금 확인할 수 있어요」(기한 지남, 파랑 굵게) 또는 「{{date}} 부터」(`yyyy.MM.dd`) · 버튼 「실행」 · 「폐기」.
  - 기한 지난 게 있으면 종 아이콘 아래 말풍선이 자동으로 뜸: 「해야 될 작업이 있습니다!」 + × (aria 「닫기」) + 첫 작업 제목 + (2건 이상) 링크 「외 {{count}}건 더 보기」 + 「실행」 · 「폐기」.
  - 「실행」 → 새 대화를 만들고 그 작업을 실행(`chat:reminder-run`). 실패 토스트 「잠시 뒤 다시 시도해 주세요」. 「폐기」 실패도 같은 문구.

- 카드 최대 4장(최대폭 420px, 아이콘 + 제목 + 설명):

  2. 남은 칸은 서버 홈 추천(`chat:home-suggest`, 로딩 중엔 스켈레톤, 20초 지나면 포기) → 없으면 기본 4장:
     | 제목 | 설명 | 클릭 시 보내는 문장 |
     |---|---|---|
     | 「캠페인 성과 보기」 | 「지난 7일간의 발송 결과를 분석합니다」 | 「최근 7일 동안 보낸 메시지의 성과를 채널별로 정리하고, 눈에 띄는 점이 있으면 짚어줘.」 |
     | 「세그먼트 만들기」 | 「조건에 맞는 세그먼트를 만들어 드립니다」 | 「최근에 활동이 줄어든 유저를 찾아서, 이탈 위험이 있는 대상을 고를 세그먼트 조건을 제안해줘.」 |
     | 「메시지 문구 쓰기」 | 「반응이 좋은 메시지 문구를 제안합니다」 | 「지금 보내려는 푸시에 쓸 문구를 두세 가지 안으로 제안하고, 각각 어떤 상황에 맞는지 알려줘.」 |
     | 「고객 여정 설계」 | 「목표에 맞는 고객 여정을 설계합니다」 | 「달성하려는 목표를 정하고, 거기에 맞는 고객 여정을 어떤 단계로 짜면 좋을지 설계해줘.」 |
- 지난 대화를 여는 중이면 「지난 대화를 불러오는 중이에요」.

### 2-7. 입력창 (하단)
- 위에 쇼트컷 칩 줄(마지막 답변이 준 추천, 클릭 = 그 문장 바로 전송)
- 여러 줄 입력(최대 8줄 자동 높이), placeholder 「무엇이든 물어보세요」 / 플랜 실행 중이면 「플랜 실행이 끝나면 다시 입력할 수 있어요」(입력 비활성). 열리면 자동 포커스.
- 아래 줄 왼쪽: 체크 「플랜모드」(툴팁 「먼저 묻고 플랜 한 장을 만듭니다」 + `⌘/Ctrl P`, 답변 중·플랜 실행 중 비활성) + 안내 「Enter 전송 · Shift + Enter 줄바꿈」
- 오른쪽: 글자수(7,200자 이상일 때만) 「{{length}} / {{max}}」, 전송 버튼(위 화살표, aria 「보내기」) - 답변 스트리밍 중엔 정지 버튼(■, aria 「중단」)
- 최대 8,000자. 넘으면 안내 자리에 빨간 「메시지가 너무 길어요. {{max}}자 안으로 줄여 주세요.」 + 전송 비활성.
- 전송 가능 = 공백 아님 & 8,000자 이하 & 답변 중 아님 & 플랜 실행 중 아님. Enter(한글 조합 중 제외)로 전송.
- 플랜 실행 중 입력창 위 띠: 깜빡이는 점 + 「플랜 실행 중 · {{current}}/{{total}} 단계」 + ` · {현재 단계 이름}` + 버튼 「파기」.

### 2-8. 메시지 · 답변 흐름
- 사용자 메시지: 오른쪽 말풍선(최대 82%).
- 보내면 즉시 사용자 메시지 추가(새 대화면 대화 목록 맨 위에 생성) → 서버가 수락하면 빈 답변 자리 생성.
  - 서버가 거절하면 답변 자리에 문구: 기본 「메시지를 보내지 못했어요. 잠시 후 다시 시도해 주세요.」 / 이미 답변 중 「앞의 답변이 끝나면 보낼 수 있어요.」 / 너무 잦음 「잠깐 사이에 너무 많이 물어봤어요. 잠시 후 다시 시도해 주세요.」 / 사용량 소진 「오늘 이 프로젝트에서 쓸 수 있는 AI 사용량을 다 썼어요. 내일 다시 이용할 수 있어요.」 / 너무 김 「메시지가 너무 길어요. {{max}}자 안으로 줄여 주세요.」
- **진행 표시(스트리밍 중)**: AI 아이콘(생각 중 애니메이션) + 한 줄 - 진행 중 단계 이름(서버 `chat:step`), 없으면 본문 나오기 전 「요청 확인 중」, 본문 나오는 중 「답변 생성 중」. 본문 전엔 보라-파랑 그라데이션이 흐르는 글씨.
- 본문: 마크다운(표·코드·인용, 굵게 보정). 끝에 깜빡이는 커서. 외부 링크는 새 탭 + 뒤에 「(도메인)」. 이미지는 alt 글자만.
  - 콜아웃 인용 `> [!caution|insight|tip|good]` → 아이콘 + 라벨 「주의」 · 「짚어둘 것」 · 「팁」 · 「권장」(노랑/파랑/진노랑/초록 계열 띠)
  - 답변이 참고한 자산 이름이 본문에 나오면 그 글자가 콘솔 내부 링크가 됨.
- 완료 후: 「{{seconds}}초 생각함」 / 「{{minutes}}분 {{seconds}}초 생각함」 (단계가 있으면 클릭해 펼침 - 단계 목록에 ✓).
- 중단하면 본문이 비어 있을 때 「답변을 중단했어요.」. 실패 시 「답변을 만들지 못했어요. 잠시 후 다시 시도해 주세요.」. 응답 중 연결이 끊기면 「연결이 끊어졌어요. 잠시 후 다시 시도해 주세요.」를 답변 끝에 붙임.
- 지난 대화가 길면 맨 위 회색 알약 「이전 대화는 표시되지 않습니다」(200개 이상 불러왔을 때). 너무 자주 불러오면 「너무 자주 불러와서 잠시 쉬어가요. 잠시 후 다시 시도해 주세요.」.
- 맨 아래에 있을 때만 새 내용 따라 자동 스크롤.

### 2-10. 질문 카드(`question`)
- 머리 「진행하기 전에 확인할게요」(서버 intro가 있으면 그것) → 질문 → 선택지 버튼들 → 자유 입력칸(placeholder 「직접 입력해도 됩니다」)
- 아래: ‹ (aria 「이전 질문」) 「{현재} / {전체}」(하드코딩 형식) › (aria 「다음 질문」) + 「답변 보내기」
- 선택지 클릭 → 그 답 저장 후 다음 질문으로. 모든 질문에 답이 있어야 「답변 보내기」 활성. 보내면 `- 질문 → 답` 줄들을 하나의 사용자 메시지로 전송.

### 2-11. 플랜모드 · 플랜 문서(`plan_document`)
- 플랜모드로 보내면 서버가 질문 → 플랜 문서를 만듦. 도킹이면 「채팅」 · 「플랜」 탭이 생김(활성 플랜이 있으면 「플랜」 탭으로 자동 전환), 전체 화면이면 오른쪽에 플랜 칸(기본 440px, 320~760 드래그, aria 「플랜 너비 조절」). 채팅 쪽 원래 자리엔 「이 플랜은 플랜 탭에 열려 있어요」 + 제목.
- 문서 내용: 제목 → 표 「목적」 · 「성과 확인」 · 「대상」 · 「채널」 · 「일정」 → 추천(마크다운) → 콜아웃 → 근거(값 + 사실) → 「실행」 단계 목록(지난 단계 흐리게, 실행 중 단계에 점) → 「검증」 박스(「실행 {{days}}일 뒤부터 확인」 + 「승인하면 예약돼요」 또는 「예약해 뒀어요」)
- 아래 상태줄:
  - 제안 상태: 「승인」 · 「파기」
  - 실행 중: 점 + 「{{current}}/{{total}} 단계 진행 중」 + 「파기」
  - 끝: 「플랜을 마쳤습니다」 / 「파기했습니다」
  - 새 버전이 나온 옛 문서: 「이전 버전 플랜이에요. 최신 플랜으로 대체됐어요」 + 「펼치기」/「접기」
- 승인하면 단계를 자동으로 하나씩 실행(화면 이동·값 채우기 포함), 끝나면 마지막 이동 대상 페이지로 이동.

### 2-12. 적용(승인) 카드 - AI가 화면 값을 바꾸자고 할 때
- 카드(대기 중 = 옅은 파랑 배경·파란 테두리): 머리 칩(필드 이름) + 대상 이름 → 변경 내용
  - 단일 값: `이전 → 이후`(이전이 비었거나 「(없음)」/「(none)」이면 이후만)
  - 여러 칸 채우기: `· 섹션 › 라벨  이전 → 이후` 목록, 6개 넘으면 「+{{count}}개 더 보기」. 대기 중에 줄에 마우스를 올리면 실제 화면의 그 입력칸에 파란 외곽선 + 스크롤.
  - 여정 초안: 노드 목록(「진입」, 노드 종류 「푸시」 · 「알림톡」 · 「브랜드 메시지」 · 「문자」 · 「이메일」 · 「인앱 메시지」 · 「웹훅」 · 「대기」 · 「이벤트 조건 분기」 · 「세그먼트 조건 분기」 · 「속성 갱신」 · 「이벤트 발생」 · 「A/B 분기」, 「{{count}}일/시간/분」, 「예 → …」/「아니오 → …」, 「계속」 · 「종료」, 「A {{a}}% · B {{b}}%」, 미설정은 「노드를 열어 설정」 · 「문구 없음」 · 「조건 미설정」)
  - 여정 노드 수정: 「삭제」 · 「추가」 · 「교체」 · 「수정」 + 대상
- 버튼: 「적용」 · 「취소」
- 결과줄: 「변경했어요.」 / 「적용하지 않았어요.」 / 「적용하지 못했어요. 화면에서 직접 확인해 주세요.」 / 「적용하지 못했어요 — {{reason}}」 / 「{{total}}개 중 {{applied}}개만 채웠어요. 못 채운 항목: {{labels}}」 / 「고친 제안으로 바꿨어요. 아래 카드를 확인해 주세요.」
- 결정 후엔 한 줄로 접힘: ✓ 또는 · + 제목 + 「{{count}}개 항목」 + 「변경」/「취소」/「대체됨」 → 클릭해 펼치면 「접기」.
- 한 답변에 변경이 2개 이상이면 번호 붙은 묶음 카드 + 「승인하고 {{count}}개 적용」(진행 중 「적용하는 중…」) · 「전부 취소」.
- 실패 사유 문구(현재 화면을 벗어났을 때 등): 「여정 편집기가 닫혀 있어 놓지 못했어요」, 「이어붙일 자리를 찾지 못했어요」, 「세그먼트 편집 화면을 벗어나 조건을 놓지 못했어요」, 「페이지 이동을 취소해서 화면을 옮기지 못했어요」 등 `common.json`의 `chat.approval.*` 전부.
- 「할 일 담기」 카드(`save_todo`): 종 아이콘 + 제목 + 설명 · 버튼 「담기」 · × (aria 「닫기」) → 결과 「해야 될 작업에 담았어요」 / 「담지 못했어요」.

### 2-13. 연결 · 세션 에러 (빨간 토스트)
- 연결 실패: 서버 코드별 - 「AI 어시스턴트에 연결하지 못했어요. 잠시 후 다시 시도해 주세요.」(기본) · 「로그인이 만료되었어요. 다시 연결하고 있어요.」 · 「이메일 인증 후 이용할 수 있어요.」 · 「이 프로젝트에서는 AI 어시스턴트를 이용할 수 없어요.」 · 「허용된 IP 주소에서만 AI 어시스턴트를 이용할 수 있어요. 관리자에게 문의해 주세요.」
- 「로그인 세션이 만료돼 채팅 연결이 끊겼어요. 다시 연결하고 있어요.」 / 「곧 로그인 세션이 만료돼요. 대화는 저장되어 있어요.」
- 연결 안 된 동안은 응답 중으로 취급(전송 불가).

## 3. AI 세그먼트 `/labs/ai-segment`

페이지 제목(heading) **없음**. 카드 2장(간격 32px): 요청 카드 → 「요청 내역」 카드.

### 3-1. 요청 카드 「AI 세그먼트」
- 설명 「원하는 세그먼트를 만들거나 모수를 확장 또는 최적화할 수 있습니다.」 + 공백 + 링크 「문서보기」(brand500, 새 탭 `https://flarelane.com/ko/docs/ai-segment/`, en은 `/en/docs/ai-segment/`)
- **시작 대상** 라디오(가로): 「세그먼트」(기본) · 「CSV 업로드」
  - 「세그먼트」: 검색 가능한 드롭다운(최대폭 320px, placeholder 「세그먼트 선택」). 목록 = 유저 세그먼트, `DEFAULT` 타입이 맨 위 + 「기본」 배지, 나머지 이름순. 고르면 오른쪽에 대상 수 「{{n}}명」(브랜드색).
  - 「CSV 업로드」: 공용 CSV 업로더(첫 열 `userId`, 추가 필수 헤더 없음). 업로드 영역·오류 문구는 `staging-behavior-new-message-templates.md`의 CSV 업로드 절과 동일.
- **프롬프트** 박스(테두리 박스, 포커스 시 브랜드색): 여러 줄 입력(최소 3줄, 최대 2000자), placeholder 「어떻게 만들까요? 예) 가을 아우터 할인 문자, 6천명, 구매 가능성 높은 사람 위주로」
  - 프롬프트가 비어 있을 때만 박스 안 아래에 **추천 카드 격자**(추천 개수만큼 열, 모바일 1열): 채널 아이콘(PUSH·SMS·KAKAO_ALIMTALK·KAKAO_BRAND_MESSAGE·EMAIL·IN_APP, 없으면 아이콘 없음) + 라벨 + 설명(각 한 줄 말줄임), 마우스 올리면 전체 prompt 툴팁(title). 클릭 → 프롬프트 칸에 prompt 채움. 글자를 치면 페이드 아웃.
  - 추천은 서버가 줌: 고른 세그먼트가 `DEFAULT` 타입이면 그 id로, 아니면 파라미터 없이 다시 요청(선택이 바뀔 때마다).
- 오른쪽 아래 「만들기」 버튼(높이 44, 흰 글씨, 파랑-하늘 그라데이션이 30초 주기로 흐름, 앞에 요술봉 아이콘)
  - 활성 조건: (세그먼트 선택됨 또는 CSV가 유효) & 프롬프트 공백 아님. 비활성/전송 중 = 흑백 50% 투명, not-allowed.
  - 클릭: (CSV면 먼저 `POST v1:/upload-csv` 파일 업로드 → filename) → `POST labs:/ai-segments {sourceType: "SEGMENT"|"CSV", segmentId?, csvKey?, csvRowCount?, prompt}` → 성공 시 폼 초기화(프롬프트 비움, 「세그먼트」로, 선택·CSV 비움) + 요청 내역 1쪽으로 이동해 다시 불러옴. **성공 토스트 없음.** 실패는 서버 메시지 토스트(429도 토스트, Sentry 제외).

### 3-2. 「요청 내역」 카드
- 표 열: (펼침 화살표 34px) · 「타이틀」 · 「상태」(120) · 「유저 수」(130) · 「생성 시간」(190) · (액션 80)
  - 타이틀: 굵은 제목 + (생성 중이면 회색 스켈레톤 막대) + 요약 한 줄(회색, `summary`가 있을 때)
  - 상태 배지(점 + 글자): 생성 중 「생성중」(보라) · 완료 「생성됨」(초록) · 실패 「실패」(빨강)
  - 유저 수: 천단위 쉼표, 값 없으면 회색 「—」(하드코딩)
  - 생성 시간: `yyyy.LL.dd HH:mm:ss`
  - 액션: 생성 중이면 스피너 / 완료면 다운로드 아이콘(secondary xs, aria 「다운로드」) / 항상 휴지통(aria 「삭제」)
- 로딩: 표 자리 스피너. 빈 목록: 공용 빈 상태(「데이터가 없습니다」).
- 페이지네이션: 10개씩, 번호 5개 표시, 최대 100쪽, 처음/끝 버튼 없음. 로딩 중 반투명 막.
- 생성 중인 요청이 하나라도 있으면 **3초마다 조용히 다시 불러옴**(로딩 표시 없이).
- 행 클릭 → 아래로 상세 펼침/접힘(여러 개 동시 펼침 가능). 생성 중 행은 클릭 안 됨(커서 기본).
- 펼친 상세(회색 배경, 최대폭 760px, 세로 타임라인 점 3개)
  1. 시작 대상 라벨 + 요청 프롬프트(15px)
     - 「전체 유저 {{n}}명」/「전체 유저」, 「세그먼트 {{name}} {{n}}명」/「세그먼트 {{name}}」, 「CSV {{name}} {{n}}명」/「CSV {{name}}」 (인원 모르면 이름만)
  2. 진행 단계 목록(90ms 간격으로 차례로 나타남): `EXPLORE` 단계는 반짝이 아이콘, 그 외는 돋보기 아이콘. 글자 속 `` `코드` ``는 회색 박스로. 마지막에 결과 한 줄(체크 아이콘):
     - 넓히기(`EXPAND`): 「대상을 넓혔습니다.」 / 「시작 대상에 {{n}}명을 새로 더했습니다.」 / 「시작 대상 밖에서 조건에 맞는 유저가 {{n}}명뿐이라 목표에 못 미쳤습니다.」 / 「시작 대상 밖에서 조건에 맞는 유저를 찾지 못해 시작 대상 그대로입니다.」
     - 좁히기: 「대상을 좁혔습니다.」 / 「시작 대상에서 {{n}}명을 뺐습니다.」 / 「시작 대상이 모두 조건에 맞아 뺀 유저가 없습니다.」 / 「시작 대상 안에서 조건에 맞는 유저가 더 없어 목표에 못 미쳤습니다.」
     - 만들기(`CREATE`): 「시작 대상에서 조건에 맞는 유저를 골랐습니다.」
  3. 결과: 실패면 서버 `failureReason`(빨강) 또는 「기준을 세우지 못해 멈췄습니다.」 / 생성 중이거나 인원 없음 「아직 뽑는 중입니다.」 / 완료 「{{n}}명」(굵게) + 결과 설명 + (목표가 있으면) 「목표 {{n}}명」
- 다운로드: CSV 다운로드 사유 모달(제목 「CSV 다운로드」, 「다운로드 사유 입력」, placeholder 「다운로드 사유를 입력해 주세요.」, 「취소」·「다운로드」) → `POST labs:/ai-segments/{id}/download-csv {reason}`(blob) → 파일명 `{제목(금지문자→_ , 60자)}.csv`. 성공 토스트 없음.
- 삭제: 브라우저 `confirm` 「이 요청을 삭제하시겠습니까? 뽑아 둔 대상도 함께 사라집니다.」 → `DELETE labs:/ai-segments/{id}` → 현재 쪽이 비면 앞 쪽으로 보정 후 다시 불러옴. 토스트 없음.
- **"세그먼트로 저장" 같은 버튼은 없음.** 결과 활용은 CSV 다운로드뿐(번들 기준).

## 확인 못 한 것
- `/labs` 인덱스 페이지: 매니페스트에 없어 404로 추정. 메뉴 부모는 이동하지 않음.
- 서버 쪽 `getServerSideProps` 리다이렉트(플래그·권한) 여부.
- 플래그가 어떤 조건(플랜·관리자 설정)으로 켜지는지 - 번들엔 프로젝트 상세의 불리언만 보임.
- AI 세그먼트 「좁히기」 방향의 실제 `direction` 값 이름(코드는 `EXPAND`·`CREATE`만 비교, 나머지는 좁히기로 처리). `ALL_USERS` 시작 대상은 요청 UI에 없는데 상세 문구엔 있음 - 어디서 생기는지 불명.
- AI 세그먼트 결과를 세그먼트로 저장하는 기능 - 번들에 없음(CSV 다운로드만).
- 캘린더 툴바 제목·「+n」 더보기 문구·주 보기 머리 형식은 FullCalendar 한국어 로케일 기본값이라 정확한 글자는 실제 화면 확인 필요.
- 캘린더 일정이 서버에서 어떤 원천(발송·예약·반복·인앱·AI 리마인더)으로 묶이는지, `href` 값 형식.
- 채팅 세션 제목 생성 규칙(첫 메시지에서 자르는 함수 `Ee` - 길이 미확인), 홈 추천 카드 `category` 값 전체 목록(아이콘 매핑에 있는 것: daily·performance·growth·onboarding·integration·integrationNext·ops·firstSend·automate·dormant·channelMix·scheduleConflict·copyAb).
- 각 위젯 카드의 세부 레이아웃(차트 종류, 표 정렬 기본값 등)은 문구만 확인, 픽셀 구조는 미확인.
- `aiAgent.json`의 「새 고객 여정 자동화 생성」 · 「고객 여정 자동화 개선 추천」 · 「이 여정으로 시작」 · 「다시 생성」 · 「적용 전/후」 등 `panel.*`·`preview.*`·`card.*`·`button.*` 키는 실험실·채팅 청크에서 안 쓰임(여정 쪽 AI 패널용으로 보이나 미확인).
- 공휴일 칸의 날짜 숫자 색 등 `cal-holiday` 클래스 세부 스타일(달력 래퍼 CSS에 빨강 `#E5484D`가 들어가 있어 공휴일 날짜가 빨갛게 보일 가능성이 큼), 모바일에서 캘린더 사이드바 처리 방식.
- 실제 픽셀 모양(색·간격)은 이 문서 범위 밖 - Figma 시안 기준.
