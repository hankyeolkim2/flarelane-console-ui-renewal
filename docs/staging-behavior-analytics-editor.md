## 2. 헤더

### 2.1 브레드크럼
- `분석 보드` (`category`) → 클릭 시 `/analytics-boards`
- 보드명 → 클릭 시 `/analytics-boards/{boardId}`. 이름 비어 있으면 「제목 없음」. 최대 폭 280px, 넘치면 말줄임. 불러오는 중엔 스켈레톤(120×20)
- 현재 통계명 (굵게, 최대 폭 440px, 클릭해도 아무 일 없음)
- 구분자는 chevron 아이콘
- **boardId가 없는 경우(보드 없이 신규 생성)**: 「분석 보드」와 보드명 crumb이 둘 다 숨고 통계명만 보인다 (`isCategoryVisible = !!boardId`)

### 2.2 통계명
- 기본 이름: 신규 모드에서 이름을 바꾸지 않았다면 현재 탭 기준 「새 인사이트」/「새 퍼널」 (탭을 바꾸면 따라 바뀐다). 편집 모드는 서버의 `report.name`. 빈 값이면 「제목 없음」
- **이름을 클릭해서 편집할 수는 없다.** ⋯ 메뉴의 「이름 수정」으로만 편집 모드에 들어간다
- 편집 모드: 밑줄(brand-500) 인풋, 폭 440px 고정, maxLength 100, 자동 포커스
  - Enter 또는 blur → 앞뒤 공백을 지운 값이 비어 있지 않고 기존과 다를 때만 반영. 빈 값이면 조용히 원래 이름으로 되돌아간다(오류 문구 없음)
  - Esc → 취소
  - 편집 모드(edit): 즉시 `PATCH` 이름 API 호출 (저장 버튼과 무관, dirty에 포함되지 않음). 응답 전까지는 입력한 이름을 낙관적으로 보여준다
  - 신규 모드(create): 로컬 상태에만 저장. 저장할 때 이 이름으로 생성된다. 이름을 한 번이라도 바꾸면 이탈 경고가 켜진다

### 2.3 ⋯ 메뉴 (more_horiz)
- 항목 (bottom-start 팝오버):
  - 「이름 수정」 → 통계명 인라인 편집 시작
  - 「삭제」 (빨간 글씨) — **편집 모드에서 report가 로드된 경우에만** 보임. 신규 모드엔 「이름 수정」만 있다
- 이름 로딩 중엔 ⋯ 버튼이 숨는다
- 삭제 확인 모달:
  - 제목: 내가 만든 통계면 「통계를 삭제하시겠습니까?」, 다른 사람이 만든 통계면(`createdByMemberId ≠ 내 id`) 「내가 생성한 통계가 아닙니다. 삭제하시겠습니까?」
  - 본문: 「삭제된 통계는 복구 불가합니다.」
  - 확인 → DELETE → 토스트 「{{name}} 통계가 삭제되었습니다.」(이름이 없으면 「제목 없음」) → 이탈 경고 우회 → `/analytics-boards/{boardId}`로 이동

### 2.4 생성자
- 「생성자:」 + 이메일의 `@` 앞부분 (예: `hk.kim`). 마우스를 올리면 같은 텍스트가 툴팁으로 뜬다
- 신규 모드: 현재 로그인 유저 이메일. 편집 모드: `report.createdByMemberEmail`. 값이 없으면 「탈퇴한 멤버」
- 로딩 중엔 스켈레톤(80×20)

### 2.5 저장 버튼
- 상태 4가지 (`saveButtonState`):
  - `SAVING` → 로딩 스피너, 비활성
  - `SAVED` → 라벨 「저장 됨」, 비활성 (편집 모드에서 저장에 성공한 직후, 다시 바꾸기 전까지)
  - `READY` → 「저장」 활성. **조건: 현재 결과 쿼리가 `SUCCEEDED`이면서 dirty일 때만**
  - `DISABLED` → 「저장」 비활성 (그 밖의 모든 경우: 바뀐 게 없음, 결과가 로딩·실패·빈 상태 등)
- dirty 판정: 현재 설정(타입·기간·단위·측정 기준·전환 인정 기간·지표·필터·타겟)을 직렬화해 기준과 비교
  - 기준 = 마지막 저장값 → 없으면 서버에서 불러온 report → 신규 모드면 처음 진입했을 때의 기본 상태
  - 값이 비어 있는 필터도 비교에는 포함된다 (쿼리에서는 빠진다, 5.2 참고)
  - 기간이 프리셋이면 프리셋 이름으로 비교한다 (날짜가 바뀌어도 「30일」은 같은 값으로 본다)
  - 이름 변경은 dirty에 포함되지 않는다
- 클릭 동작:
  - 편집 모드 → `PUT` config → 성공: 상태 `SAVED`(「저장 됨」), 토스트 「저장 완료!」 / 실패: `IDLE`로 복귀 (버튼이 다시 「저장」)
  - 신규 모드 + URL에 boardId 있음 → 보드 선택 모달 없이 그 보드에 바로 `POST`, 토스트 「저장 완료!」, `router.replace('/analytics-boards/{boardId}/reports/{newId}')`. 이 경로에선 클라이언트의 30개 한도 체크가 없다 (서버 동작은 확인하지 못함)
  - 신규 모드 + boardId 없음 → 「통계를 저장할 보드 선택」 모달

### 2.6 보드 선택 모달 (신규 모드, boardId 없음)
- 제목 「통계를 저장할 보드 선택」
- 검색창 (돋보기, 자동 포커스) placeholder 「보드 이름, 생성자 검색」 — 보드명 또는 생성자(이메일 @ 앞부분)로 필터링. 대소문자와 `_`는 무시하고 부분 일치
- 보드 목록: 모달을 열 때 전체 보드를 `sortBy=updatedAt`, `limit=30` 페이지로 끝까지 불러온다 (최근 편집순)
  - 행(높이 58): 보드명(없으면 「제목 없음」) / 생성자 + 오른쪽에 「{{count}}개의 통계」
  - 클릭하면 선택(하이라이트). 하나만 선택된다
  - 로딩 중엔 스피너(32), 검색 결과가 없으면 「검색 결과가 없습니다」
- 목록 맨 위의 「+ 새 보드 생성」(brand 색) 행:
  - 클릭 → 인라인 인풋(placeholder 「새로 생성할 보드」, maxLength 100, 자동 포커스)
  - Enter: 앞뒤 공백 지운 값이 비어 있으면 빨간 테두리와 「유효하지 않은 이름입니다.」 표시. 입력하면 오류가 사라진다. 값이 있으면 보드 생성 `POST` → 새 보드를 목록 맨 앞에 넣고 **자동 선택**, 검색어 초기화, 인풋 닫힘
  - Esc → 인풋 닫기 (모달은 닫히지 않음)
  - blur → 오류 상태가 아니면 인풋 닫기 (입력값 버림)
- 하단 버튼: 「취소」(secondary) → 모달 닫기 / 「저장」 → **보드가 선택되지 않았거나 새 보드 인풋이 열려 있으면 비활성**
  - 선택한 보드의 `reportsCount ≥ 30` → 보드 한도 모달을 띄우고 저장 중단
  - 그 외 → 그 보드에 `POST` → 토스트 「저장 완료!」 → `router.replace('/analytics-boards/{boardId}/reports/{newId}')`
- 키보드 Esc: 한도 모달이 열려 있으면 그것만 닫고, 아니면 보드 선택 모달을 닫는다

## 3. 인사이트 / 퍼널 탭
- 탭 라벨 「인사이트」/「퍼널」 (`create.insight`, `create.funnel`), 쿼리 패널 맨 위
- **신규·편집 모드 모두에서 바꿀 수 있다** (모드 제한 없음)
- 탭을 바꿔도 **아무것도 초기화되지 않는다**: 지표(이벤트·필터), 측정 기준, 전환 인정 기간, 타겟, 기간, 단위가 그대로 남는다
- 탭을 바꾸면 달라지는 것:
  - 단위 select: 인사이트에서만 보인다 (퍼널에선 숨김. 값은 내부에 남는다)
  - 전환 인정 기간 섹션: 퍼널 + 「총 이벤트 수」일 때만 보인다
  - 쿼리 실행 조건: 인사이트는 지표 ≥1개, 퍼널은 ≥2개
  - 결과 화면: 차트+표 형태가 다르다
  - 신규 모드에서 이름을 바꾸지 않았다면 기본 이름(새 인사이트 ↔ 새 퍼널)
  - CRM 배너는 인사이트에서만 뜬다 (퍼널은 단계별 경고 아이콘)
- 편집 모드에서 타입을 바꾸면 dirty가 되고, 저장하면 PUT에 바뀐 type이 실린다

## 4. 툴바

### 4.1 기간 표시 + 날짜 범위 피커
- 트리거: 달력 아이콘 + `yyyy-MM-dd ~ MM-dd` (시작·종료가 같은 해일 때) 또는 `yyyy-MM-dd ~ yyyy-MM-dd` (해가 다를 때) + ▾
- 클릭하면 공용 RangeDatePicker 팝오버가 열린다
  - 왼쪽: 범위 선택 달력(inline). `minDate = 오늘 − 365일`, `maxDate = 오늘` (미래 불가)
  - 오른쪽 「기간설정」 프리셋 리스트 (common): 「오늘」「어제」「최근 7일」「최근 30일」「최근 90일」「최근 1년」 — 이 리스트는 피커 안의 선택값만 바꾼다. 현재 범위와 일치하는 항목이 하이라이트된다(brand-500, 굵게)
    - 주의: 피커의 「최근 7일」은 `오늘−7 ~ 오늘`(8일 범위)이라 툴바의 「7일」(`오늘−6 ~ 오늘`)과 다르다. 「최근 30일」 등도 같은 방식
  - 「날짜」: 시작/종료 텍스트 인풋 (placeholder `yyyy-MM-dd`, 숫자만 입력하면 `-`가 자동으로 들어감, 최대 10자). 미래 날짜는 오늘로, minDate 이전은 minDate로 보정
    - 오류 문구: 「날짜 형식이 올바르지 않습니다」, 「시작일이 종료일보다 늦을 수 없습니다」
  - 하단 「취소」 / 「확인」 — 시작·종료 중 하나라도 비었거나, 오류가 있거나, 인풋 입력이 덜 끝났으면(1~9자) 「확인」 비활성
  - 피커 아래 타임존 표시 (`moment.tz.guess()`)
  - 바깥(오버레이) 클릭 = 취소
- 「확인」으로 정한 범위는 **항상 `preset: null`(직접 지정)** 이 된다 → 툴바 프리셋 버튼 4개가 모두 하이라이트 해제. 범위가 프리셋과 같은 날짜여도 마찬가지
- 최대 범위를 따로 제한하지 않는다. minDate 때문에 사실상 최대 366일

### 4.2 프리셋 버튼 (툴바, 피커 오른쪽에 붙은 세그먼트)
- 순서: 「어제」「오늘」「7일」「30일」
- 계산 (클릭한 시각 기준):
  - 어제: 어제 ~ 어제 (1일)
  - 오늘: 오늘 ~ 오늘 (1일)
  - 7일: 오늘−6 ~ 오늘 (7일)
  - 30일: 오늘−29 ~ 오늘 (30일)
- 선택된 프리셋은 font-weight 500 + 강조 배경, 나머지는 400
- 기본값: **30일** (신규 진입 시 30일이 하이라이트)
- 저장할 때 프리셋은 `{ preset }`으로만 저장된다 → 다시 열면 그날 기준으로 다시 계산된다. 직접 지정한 범위는 `{ from, to }`(yyyy-MM-dd)로 저장된다
- 기간을 바꾸면 단위가 새 기간에서 허용되지 않을 때 그 기간의 기본 단위로 자동 교체된다 (아래 표)

### 4.3 단위(granularity) select — 인사이트 전용
- 오른쪽 정렬, 폭 80, 옵션 순서 「시간」「일」「월」. 허용되지 않는 옵션은 회색 비활성으로 보인다
- 기간 일수(시작~종료 포함) 기준 허용 규칙:

| 기간 일수 | 허용 | 기본값 |
|---|---|---|
| 1일 | 시간 | 시간 |
| 2~30일 | 시간, 일 | 일 |
| 31~60일 | 일, 월 | 일 |
| 61일 이상 | 일, 월 | 월 |

- 신규 기본값: 기간 30일 → 「일」
- 기간을 바꿨을 때 현재 단위가 허용 목록에 있으면 그대로 두고, 없으면 기본값으로 바꾼다

## 5. 쿼리 패널

### 5.0 공통 섹션 헤더
- 섹션 제목 + (있으면) 도움말 ? 아이콘(마우스를 올리면 툴팁, 최대 폭 240px, HTML 링크 포함) + (데이터 그룹만) 오른쪽 「준비중」 배지
- 도움말 문구:
  - 분석 지표: 「이벤트(유저 행동)를 지정하여 무엇을 분석할지 설정합니다. 가이드」 (가이드 → https://flarelane.com/ko/docs/data-analytics/metrics/, 새 탭)
  - 타겟 유저: 「전체 유저 중 어느 집군을 대상으로 집계할지 설정합니다. 가이드」 (→ https://flarelane.com/ko/docs/data-analytics/target-users/)
  - 데이터 그룹: 「지표를 특정 속성 기준으로 그룹화해 시각화합니다.」
  - 측정 기준·전환 인정 기간: 도움말 없음

### 5.1 분석 지표 (이벤트 블록)
- 블록 구성: [드래그 핸들] [번호 배지 1,2,3…] [이벤트명] … 오른쪽 액션: [필터 추가 아이콘(brand-500)] [X 삭제(gray-400)]
- 최대 10개 (인사이트·퍼널 공통). 퍼널 최소 개수는 UI에서 막지 않는다 (2개 미만이면 결과가 빈 상태로 남을 뿐)
- 「+ 이벤트 추가」 (tertiary 버튼, 섹션 하단 중앙):
  - 비활성 조건: (지표 수 + 추가 중인 빈 블록) ≥ 10, 또는 드래그 중
  - 클릭 → 목록 끝에 빈 블록(배지 = 다음 번호, placeholder 「이벤트 선택」, X 버튼)이 생기고 이벤트 선택 팝오버가 바로 열린다
  - 이벤트를 고르면 지표가 추가되고(필터 없음) 빈 블록이 사라진다. 팝오버를 닫거나 X를 누르면 아무것도 추가되지 않는다
- 블록의 빈 곳(필터 행·액션 버튼 제외)이나 이벤트명을 클릭 → 이벤트 선택 팝오버(현재 이벤트가 선택 표시) → 다른 이벤트를 고르면 교체. **다른 이벤트로 바꾸면 그 블록의 필터가 모두 지워진다** (같은 이벤트면 유지)
- X → 지표 즉시 삭제 (확인 없음). 번호가 다시 매겨진다
- **드래그 재정렬: 지표가 2개 이상이면 인사이트·퍼널 모두 가능** (퍼널 전용이 아님)
  - 핸들은 블록 왼쪽, 평소엔 숨어 있다가 hover 시 보인다(grab 커서). 잡으면 grabbing 커서, 드래그 중엔 다른 블록에 hover 반응이 없다
  - 마우스 기반(mousedown/move/up): 잡은 블록이 포인터를 따라 움직이고, 지나가는 블록은 0.16s `cubic-bezier(0.2,0,0,1)`로 밀려나며, 놓을 자리에 placeholder 슬롯이 표시된다. 드래그 중에는 배지 번호가 새 순서로 미리 바뀐다
  - 놓으면 순서가 확정된다(같은 자리면 변화 없음). 블록 사이 간격은 8px
  - 1개뿐이면 핸들 자리만 비워 둔다
- 이벤트 표시명: `name`이 있으면 name, 없으면 `channel.action` (channel이 없으면 action)

#### 이벤트 선택 팝오버
- 폭 680, 블록 기준 bottom-end, 오프셋 6px, 바깥을 클릭하면 닫힌다
- 상단 검색 (돋보기, 자동 포커스) placeholder 「이벤트 검색」 — 이름 부분 일치, 대소문자·`_` 무시. 팝오버를 열 때마다 검색어 초기화
- 본문 높이 388, 좌: 이벤트 리스트 / 우: 상세 패널(폭 256)
  - 리스트 행: 이벤트 아이콘 + 이름. 현재 선택된 이벤트 = brand-50 배경 + brand-500 글자(열 때 그 행으로 스크롤). hover한 행이 하이라이트되고, hover가 없으면 첫 행이 하이라이트된다
  - 상세 패널: 하이라이트된 이벤트의 타입 라벨 「이벤트」, 아이콘(20, brand-400), 이름, 「최근 발생 횟수 ({{days}}일)」: 값(천 단위 콤마, ko-KR). `days`는 서버 카탈로그의 `windowDays`
  - 「최근 발생 횟수」는 리스트 컬럼이 아니라 우측 상세 패널에만 있다
- 상태: 로딩 → 스피너 / 실패 → 「데이터를 불러오지 못했습니다.」 + 「재시도」 / 이벤트가 하나도 없음 → 「측정할 데이터가 없습니다. 데이터를 연동해주세요.」 / 검색 결과 없음 → 「검색 결과가 없습니다」
- 키보드 탐색: 코드에서 확인되지 않음 (hover와 클릭만)

#### 필터 (지표 블록 / 타겟 이벤트 블록 공통)
- 필터 추가 아이콘 클릭 → 블록 아래에 새 필터 행이 생기고 **속성 팝오버가 바로 열린다**
  - 속성을 고르지 않고 팝오버를 닫으면 그 빈 행은 사라진다
  - 속성을 고르면 필터가 생성되고(연산자 `=`, 값 없음) **값 팝오버가 자동으로 열린다**
- 필터 행: [속성 select(폭 106)] [연산자 select(폭 90)] [값 select] [X]
  - 속성 placeholder 「속성 선택」, 값 placeholder 「값 선택」
  - 값 select를 누를 때 속성이 없으면 속성 팝오버가 열린다
  - 이미 있는 필터의 속성을 다른 것으로 바꾸면 값이 비워지고 값 팝오버가 열린다 (같은 속성을 다시 고르면 값 유지)
  - X → 필터 즉시 삭제
- 필터 개수 제한: 코드에 없음 (무제한)
- 필터끼리의 결합(AND/OR) 표시: UI에 없음. 서버로는 배열로만 보낸다
- **값이 0개인 필터는 쿼리에서 빠진다** (dirty 비교에는 포함)

**속성 팝오버** (폭 360, 본문 높이 280)
- 검색 「속성 검색」. 검색어가 없으면 상단에 「모든 속성」 헤더
- 해당 이벤트(domain/action/channel)의 속성 목록을 열 때마다 API로 불러온다
- 상태: 로딩 / 실패(재시도) / 「측정할 데이터가 없습니다. 데이터를 연동해주세요.」 / 「검색 결과가 없습니다」
- 클릭하면 선택(선택 중인 속성은 brand 표시)

**연산자 select** (common 라벨): `=`(EQ, 기본) / `≠` / `>` / `≥` / `<` / `≤` / 「이 중에 하나」(INCLUDES). 연산자를 바꿔도 값은 유지된다

**값 팝오버** (폭 360, 높이 486, 하단 「적용」 버튼)
- 검색 「속성값 검색」 — 서버 검색(`q`), 입력 후 300ms 디바운스 (검색어가 비면 즉시)
- 「전체 선택」 체크박스 (보이는 값이 있을 때만): 체크 / 해제 / 부분(indeterminate) 3상태. 전체 선택도 100개 한도까지만 체크된다
- 값 행: 체크박스 + 값. LIST 타입 값(`['a','b']`)은 `a, b`로 풀어서 보여준다
- 이미 선택한 값 중 현재 로드된 목록에 없는 값은 (검색어가 없을 때) 목록 맨 위에 따로 보인다. 그다음 선택된 로드값, 그다음 미선택 값 순서
- **최대 100개 선택**: 100개가 차면 선택되지 않은 행이 비활성이 된다
- 서버가 잘라서 보냈으면(`truncated`) 하단에 「상위 100개만 표시됩니다. 검색으로 좁혀보세요.」
- 빈 상태: 검색 중이면 「검색 결과가 없습니다」, 아니면 「측정할 데이터가 없습니다. 데이터를 연동해주세요.」
- 「적용」을 눌러야 반영된다. 바깥 클릭으로 닫으면 체크한 내용(draft)은 버려진다
- 값 select 라벨: 선택값을 `a`, `a, or b`, `a, b, or c` 형식으로 이어 붙이고, 넘치면 말줄임 + 툴팁

### 5.2 측정 기준
- 2칸 세그먼트: 「사용자 수」(UNIQUE_USER) | 「총 이벤트 수」(TOTAL_COUNT). 선택된 칸은 font-weight 700 + 강조 배경
- 기본값: 두 타입 모두 **사용자 수** (스테이징 퍼널 리포트 `새 퍼널`은 저장값이 「총 이벤트 수」였다)
- 결과 단위: 사용자 수 = 「명」, 총 이벤트 수 = 「회」

### 5.3 전환 인정 기간 (퍼널 + 총 이벤트 수일 때만)
- **퍼널이면서 측정 기준이 「총 이벤트 수」일 때만 섹션이 보이고, 그때만 쿼리·저장에 `conversionWindow`가 들어간다.** 퍼널 + 사용자 수에서는 섹션이 숨는다 (값은 내부에 남는다)
- 숫자 인풋 + 단위 select(폭 80, 옵션 순서 「일」「시간」)
- 기본값 `7` / 「일」
- 인풋에는 숫자만 입력된다 (`/^\d+$/`가 아니면 무시, 빈 값은 허용)
- 반영 시점: Enter 또는 blur
  - 비어 있거나 범위를 벗어나면 빨간 테두리 + 오류 문구 (값은 반영 안 됨): 일 「1~30일까지 적용할 수 있습니다.」 / 시간 「1~720시간까지 적용할 수 있습니다.」
  - 범위 안이면 오류를 지우고 반영
- Esc → 마지막으로 반영된 값으로 되돌리고 오류 해제, 포커스 해제
- 단위를 바꾸면 현재 인풋값(비었거나 0이면 마지막 반영값)을 새 단위 범위로 잘라서(clamp) 즉시 반영. 예: 30일 → 시간 = 30시간, 720시간 → 일 = 30일

### 5.4 타겟 유저
- 기본값: 타겟 그룹 없음 (= 전체 유저). 섹션엔 「+ 타겟 그룹 추가」 버튼만 있다
- 최대 그룹 10개. (그룹 수 + 추가 중인 빈 그룹) ≥ 10이면 버튼 비활성
- 논리: **그룹끼리는 OR, 그룹 안의 블록끼리는 AND** (`{connector:"OR", groups:[{connector:"AND", blocks}]}`). 화면에 AND/OR 라벨은 없고 블록 사이에 구분선만 있다

#### 그룹 추가
- 「+ 타겟 그룹 추가」 → 빈 그룹 카드(헤더: 번호 배지 + 「타겟 그룹」, X) + 타겟 선택 팝오버가 바로 열린다
- 선택하면 그 대상을 첫 블록으로 하는 그룹이 생긴다. 닫거나 X를 누르면 취소

#### 그룹 카드
- 헤더: [번호 배지] 「타겟 그룹」 … [필터 아이콘(brand) = 이 그룹에 블록 추가] [X = 그룹 삭제]
- 블록 추가: 구분선 + 빈 블록(placeholder 「타겟 선택」) + 타겟 선택 팝오버. 고르면 AND 블록이 추가된다
- 블록 X → 블록 삭제. **그룹의 마지막 블록을 지우면 그룹도 사라진다**
- 블록 본문(액션 버튼 제외)을 클릭 → 타겟 선택 팝오버 → 다른 대상으로 교체 (같은 이벤트를 다시 고르면 필터 유지, 그 밖에는 초기화)
- 블록 종류별 표시:
  - 이벤트: 배지 「이벤트」 + 이벤트명 + 필터 추가/X. 필터 UI는 5.1과 같다
  - 세그먼트: 배지 「세그먼트」 + 세그먼트명 (로딩 중엔 스켈레톤 120). 세그먼트가 삭제됐으면 placeholder 색으로 「삭제된 세그먼트」. 필터 없음
  - 유저/기기 속성·태그: 배지 「유저」/「기기」 + 속성명(segment 네임스페이스 라벨, 태그면 태그 키) + 아래에 조건 편집기 (5.4.2)

#### 5.4.1 타겟 선택 팝오버
- 폭 680. 상단 탭 5개: 「전체」「이벤트」「세그먼트」「유저」「디바이스」 (활성 탭은 font-weight 600 + 밑줄). 열 때마다 「전체」 탭·빈 검색어로 초기화
- 검색 placeholder 「이벤트 혹은 속성 검색」 (세그먼트는 이름 또는 ID로 검색)
- 탭별 섹션 (섹션 헤더 라벨):
  - 전체: 「이벤트」, 「세그먼트」, 「유저」(유저 속성 + 유저 태그), 「기기」(기기 속성 + 기기 태그)
  - 이벤트: 「모든 이벤트」
  - 세그먼트: 「모든 세그먼트」 (유저 타입 + 디바이스 타입 세그먼트를 합친 목록)
  - 유저: 「유저 속성」, 「유저 태그」 (태그 섹션은 프로필 카탈로그 로드에 성공한 뒤에만)
  - 디바이스: 「기기 속성」, 「기기 태그」 (기기 태그 = `@device_`로 시작하는 태그 키)
- 섹션마다 따로 로딩 스피너 / 실패 시 「재시도」. 로드에 성공했는데 항목이 0개인 섹션은 숨긴다
- 모든 섹션이 로드됐는데 항목이 0개 → 검색 중이면 「검색 결과가 없습니다」, 아니면 「측정할 데이터가 없습니다. 데이터를 연동해주세요.」
- 아이콘: 이벤트 / 세그먼트 / 태그 / 유저 속성 / 기기 속성 각각 다르다. 선택 항목은 brand 색
- 우측 상세 패널: **「전체」「이벤트」「세그먼트」 탭에서만** 보인다
  - 이벤트: 「이벤트」 + 이름 + 「최근 발생 횟수 ({{days}}일)」
  - 세그먼트: 「세그먼트」 + 이름 + 「세그먼트 ID」: id
  - 속성·태그를 하이라이트하면 빈 패널

#### 5.4.2 유저/기기 조건 편집기 (블록 아래)
- 속성 타입별 UI:
  - `BIRTHDAY`: 고정 텍스트 「이 오늘이면」 (편집 없음)
  - `IS_TEST`·`IS_SMS_UNSUBSCRIBED`·`IS_SUBSCRIBED`: True / False 토글 (기본 True)
  - `PLATFORM`: 고정 텍스트 「is」 + 값 단일 선택
  - `COUNTRY_CODE`·`LANGUAGE_CODE`·`WEB_BROWSER`: 연산자 select + 값 단일 선택 (국가는 ko 이름, 언어는 `ko (한국어)` 형식)
  - `TAG`(유저/기기 태그): 연산자 select + 연산자에 따라
    - 「다음 중 하나를 포함」 등 다중 연산자(INCLUDES / CONTAINS_ANY_OF / CONTAINS_NONE_OF): 값 다중 선택 + 적용. 값에 콤마는 쓸 수 없고, 이어 붙인 길이 ≤ 500자. CONTAINS_ANY_OF / CONTAINS_NONE_OF는 최대 5개이며, 검색어 자체를 패턴 값으로 넣는 「"{{keyword}}"이 들어가는 값」 행(「{{count}}개 일치」 표시)이 있고 「전체 선택」은 없다
    - EXIST / NOT_EXIST(「가 존재하면」/「가 존재하지 않으면」): 값 입력 없음
    - IN_THE_LAST_N_HOURS / AFTER_HOURS / REMAIN_HOURS: 시간 숫자 인풋 (placeholder 「시간」, 포커스가 빠지면 `24h`처럼 표시)
    - AFTER / BEFORE: 날짜(yyyy-MM-dd) + 시:분 인풋 (바꾸면 기본값 = 현재 시각)
    - 그 밖: 값 단일 선택 (맨 위에 「값이 비어있음」 = 빈 문자열 선택 가능)
    - 태그 기본 연산자는 EQ
  - 그 밖의 속성: 연산자 select + 텍스트 인풋 「값 입력」 (콤마는 자동으로 지워짐). `*_WITHIN_HOURS` 류는 「시간」 인풋. EXIST / NOT_EXIST면 인풋 없음
- 연산자 목록과 라벨은 서버 프로필 카탈로그와 `segment` 네임스페이스를 따른다 (세그먼트 편집기와 같은 체계). 정확한 연산자 목록은 서버 데이터에 따라 달라서 여기서는 확정하지 못함
- 값이 없는 불완전한 조건은 쿼리에서 빠진다 (그룹이 비면 그룹도 빠진다)

### 5.5 데이터 그룹
- 제목 옆 도움말 + 오른쪽 「준비중」 배지
- 회색 비활성 select 모양(placeholder 「속성 선택」 + ▾), 클릭해도 반응 없음

## 6. 결과 영역

### 6.1 쿼리 실행
- **설정이 바뀌면 자동으로 실행된다. 디바운스 없음** — 설정 직렬화 키가 바뀔 때마다 즉시 새 쿼리를 보내고 진행 중이던 결과는 버린다
- 실행 조건: 타임존을 알고(프로젝트 상세 로드 후) + 인사이트 지표 ≥1 / 퍼널 지표 ≥2. 조건이 안 되면 EMPTY
- `POST /analytics/query` → `status: PROCESSING`이면 1.5초 간격으로 다시 요청. 도중에 서버의 configHash가 바뀌면 FAILED
- 편집 모드에서 report를 불러오는 동안은 LOADING
- 쿼리에 빠지는 것: 값 0개 필터, 불완전한 타겟 조건

### 6.2 상태별 화면 (결과 카드)
- EMPTY: 「통계 생성을 위해 분석 지표에서 이벤트를 선택하세요.」 + 링크 「인사이트 사용 방법 확인하기.」 / 「퍼널 사용 방법 확인하기.」 (→ flarelane.com/ko/docs/data-analytics/insight-tips/ 또는 funnel-tips/, 새 탭). 퍼널 지표가 1개일 때도 같은 화면
- LOADING: 스피너(48) + 「데이터가 많을 경우 최대 10분이 걸릴 수 있습니다.」
- FAILED: 「데이터를 불러오지 못했습니다.」 + 링크 「문제가 계속될 경우, 문의하기.」 (→ https://help.flarelane.co.kr) + 「재시도」 버튼(secondary xs, 새로고침 아이콘)
- SUCCEEDED: 아래 6.3 / 6.4. 카드는 내용 높이에 맞추고 패딩 24/20. 다른 상태에선 세로 가운데 정렬

### 6.3 인사이트 결과
- 범례: 시리즈마다 색 스와치(12×2) + 「1. 이벤트명」 (번호 = 지표 순서). 항목 최대 폭 198, hover 시 해당 시리즈 강조
- 라인 차트 (recharts, 높이 368):
  - 시리즈 색 팔레트(지표 순서대로 반복): `#597AB6 #018D87 #9E6393 #98742B #826DAE #2486A7 #458C5F #758238 #AB6645 #AC606D`
  - 선 굵기 2, linear. hover하지 않은 시리즈는 opacity 0.5. 버킷이 1개면 점(r3)으로 표시
  - 가로 그리드만 있음. Y축 tick 5개, 1·2·2.5·5×10ⁿ 단위로 자동 계산, 1k / 1.2M 형식. 데이터가 0이면 0~4,000
  - X축 라벨 형식(ko): 시간 `h aa`, 일 `M.d`, 월 `M`. 간격은 기간 길이·단위별 규칙을 따른다 (1일·시간 = 2칸 간격, ≤7일·시간 = 날짜만 24칸 간격, ≤30일·일 = 3칸 간격, 61~180일·일 = 매월 1회, 181~365일·일 = 2개월마다 등)
  - 툴팁: 마우스에서 가장 가까운 시리즈의 점 기준으로, 오른쪽이 부족하면 왼쪽으로 뒤집는다. 내용 = 색 막대 + 시리즈명 / 날짜(`yy.M.d`, 월이면 `yy.M`, 시간이면 `yy.M.d h aa`) / 값(콤마) + 「명」 또는 「회」
- 표 (차트 아래, 오른쪽 위에 「CSV 추출」):
  - 열: 「이벤트」(320px, 왼쪽 고정) | 「평균」(120px, 고정, 소수 1자리 + 콤마) | 버킷별 열(100px, 헤더 = 일 `M.d` / 월 `M` / 시간 `M.d h aa`)
  - 셀 값: 천 단위 콤마. 셀에는 단위(명/회)를 붙이지 않는다
  - 행 높이 44. 행 hover ↔ 차트 시리즈 강조, 차트 hover ↔ 해당 버킷 열 강조

### 6.4 퍼널 결과
- 단계 리스트(차트):
  - 단계마다: 라벨 「N. 이벤트명」 + (CRM 이벤트이고 기간 시작일 < 2026-05-01이면) 경고 아이콘(14). 아이콘 hover → 「해당 데이터는 5.1 부터 수집되어 전환율이 실제보다 낮게 표시될 수 있습니다.」
  - 전환율(1단계 = 「100%」, 그 밖은 `x.x%`, 값이 없으면 「-」) + 수(1k/1.2M 축약)
  - 가로 막대(높이 28): 폭 = 해당 단계 수 ÷ 1단계 수. 색은 단계 순서대로 `#1D4289 → #2D5093 → … → #B5C4E3` (10단계 블루 그라디언트)
  - 2단계부터 막대 위(단계 사이)에 「이탈 {{rate}}」 (이전 단계의 이탈률)
  - 막대 hover → 툴팁: 단계명 / 전환율 + 「전환」 / 캡션 「N명」 또는 「N회」(축약)
  - 막대 오른쪽 남은 영역(이탈 영역, 2단계부터) hover → 빨간(red-600) 툴팁: 단계명 / 이탈률 + 「이탈」 / 이탈 수
- 표:
  - 헤더: 「단계」(160, 고정) | 「총 전환율」(120, 고정) | 1단계 이벤트명(200) | 「1 → 2」「2 → 3」…(140씩)
  - 행 1개(높이 60): 「모든 단계」 | 전체 전환율 | 1단계 수(콤마) | 각 단계 전환율 + 그 아래 수(콤마)
  - 열 hover ↔ 차트 단계 강조, 행 hover = 행 강조
- 오른쪽 위 「CSV 추출」

### 6.5 CSV 추출
- 버튼 「CSV 추출」 (tertiary sm, download 아이콘), 진행 중엔 로딩 표시. 결과가 SUCCEEDED일 때만 보인다
- 동작: 같은 config로 CSV 쿼리 POST(편집 모드면 reportId 포함) → 파일이 준비될 때까지 10초 간격으로 최대 1,000회 다시 요청
  - 준비되면 BOM(UTF-8) 붙은 CSV 다운로드. 파일명: `{통계명}_{yy.MM.dd}-{yy.MM.dd}.csv` (통계명의 `\ / : * ? " < > |`는 `_`로 바꾸고, 끝의 `…`는 제거)
  - 실패: 토스트 「CSV 생성에 실패했습니다. 잠시 후 다시 시도해주세요.」 / 횟수 초과: 「CSV 생성 시간이 초과되었습니다. 잠시 후 다시 시도해주세요.」
- CSV 내용(열 구성)은 서버가 만든다 → 번들에서 확인 불가

## 7. 그 밖의 동작
- 팝오버 공통: `fixed` 포지셔닝, 기본 bottom-end, 바깥 클릭으로 닫힘. 열려 있는 블록 안의 액션 영역(`data-own-click`)을 클릭해도 블록의 기본 클릭(선택기 열기)이 실행되지 않는다
- 저장 성공 뒤 신규 → 편집 URL로 replace하면 다시 마운트되어 report를 불러오고 쿼리가 재실행된다
- 문자열 검색 규칙(이벤트·속성·보드·타겟 공통): 소문자로 바꾸고 `_`를 지운 뒤 부분 일치
- 숫자 형식: 표·툴팁 값 = `toLocaleString("ko-KR")`, 축·퍼널 수 = 1k/1.2M 축약, 비율 = 소수 1자리 %
- 분석 이벤트 로깅(report_opened / report_edited / report_saved / report_exported / report_loaded / report_exited / report_deleted)이 있지만 화면 동작과는 무관
